# ROS 2 Action Generation

## Introduction

Once the LLM has planned a sequence of actions based on natural language commands, the next step is to convert these plans into actual ROS 2 actions that can be executed by the robot. This module covers how to generate and execute ROS 2 actions from LLM-planned sequences.

## Understanding ROS 2 Actions

### Action vs. Topic vs. Service

In ROS 2, there are three main communication patterns:

1. **Topics**: Publish-subscribe, for continuous data streams
2. **Services**: Request-response, for synchronous operations
3. **Actions**: Goal-feedback-result, for long-running operations with status updates

For VLA systems, actions are particularly important because they provide feedback during execution and handle long-running tasks like navigation or manipulation.

### Action Structure

An action consists of three parts:
- **Goal**: What the action should accomplish
- **Feedback**: Status updates during execution
- **Result**: Final outcome of the action

## Implementing Action Generation

### Action Client Implementation

First, let's implement a client that can execute actions generated by the LLM:

```python
import rclpy
from rclpy.action import ActionClient
from rclpy.node import Node
from geometry_msgs.msg import PoseStamped
from nav2_msgs.action import NavigateToPose
from sensor_msgs.msg import Image
from std_msgs.msg import String
from rclpy.qos import QoSProfile
from builtin_interfaces.msg import Duration

class VLAActionExecutor(Node):
    def __init__(self):
        super().__init__('vla_action_executor')

        # Action clients for different robot capabilities
        self.nav_client = ActionClient(self, NavigateToPose, 'navigate_to_pose')
        self.manipulation_client = ActionClient(self, ManipulateObject, 'manipulate_object')  # Custom action

        # Publishers for intermediate communication
        self.status_pub = self.create_publisher(String, 'vla_status', 10)

        # Service clients for auxiliary functions
        self.object_detection_client = self.create_client(DetectObjects, 'detect_objects')

    def execute_action_plan(self, action_plan):
        """Execute a sequence of actions from the LLM plan"""
        for i, action in enumerate(action_plan.get('actions', [])):
            self.get_logger().info(f'Executing action {i+1}/{len(action_plan["actions"])}: {action["action_type"]}')

            result = self.execute_single_action(action)

            if not result.success:
                self.get_logger().error(f'Action failed: {action["action_type"]}')
                return False

        self.get_logger().info('All actions completed successfully')
        return True

    def execute_single_action(self, action):
        """Execute a single action from the plan"""
        action_type = action['action_type']

        if action_type == 'navigate_to':
            return self.execute_navigation_action(action)
        elif action_type == 'grasp_object':
            return self.execute_manipulation_action(action)
        elif action_type == 'detect_objects':
            return self.execute_detection_action(action)
        elif action_type == 'request_clarification':
            return self.execute_clarification_action(action)
        else:
            self.get_logger().error(f'Unknown action type: {action_type}')
            return ActionResult(success=False, message=f'Unknown action type: {action_type}')

    def execute_navigation_action(self, action):
        """Execute navigation action"""
        # Wait for action server
        if not self.nav_client.wait_for_server(timeout_sec=5.0):
            return ActionResult(success=False, message='Navigation server not available')

        # Create goal
        goal_msg = NavigateToPose.Goal()
        target_location = action['parameters'].get('target', 'unknown')

        # In a real system, you would convert location names to coordinates
        # This is a simplified example
        goal_msg.pose.header.frame_id = 'map'
        goal_msg.pose.header.stamp = self.get_clock().now().to_msg()

        # Set target pose (simplified)
        if target_location == 'kitchen':
            goal_msg.pose.pose.position.x = 2.0
            goal_msg.pose.pose.position.y = 1.0
        elif target_location == 'living_room':
            goal_msg.pose.pose.position.x = 0.0
            goal_msg.pose.pose.position.y = 0.0
        else:
            # Try to find coordinates for the location
            coords = self.get_coordinates_for_location(target_location)
            if coords:
                goal_msg.pose.pose.position.x = coords[0]
                goal_msg.pose.pose.position.y = coords[1]
            else:
                return ActionResult(success=False, message=f'Unknown location: {target_location}')

        # Send goal
        goal_future = self.nav_client.send_goal_async(goal_msg)

        # Wait for result
        rclpy.spin_until_future_complete(self, goal_future)
        goal_handle = goal_future.result()

        if not goal_handle.accepted:
            return ActionResult(success=False, message='Navigation goal rejected')

        result_future = goal_handle.get_result_async()
        rclpy.spin_until_future_complete(self, result_future)

        result = result_future.result().result
        return ActionResult(success=True, message='Navigation completed')

    def execute_manipulation_action(self, action):
        """Execute manipulation action"""
        if not self.manipulation_client.wait_for_server(timeout_sec=5.0):
            return ActionResult(success=False, message='Manipulation server not available')

        goal_msg = ManipulateObject.Goal()
        obj_name = action['parameters'].get('object', 'unknown')

        # Set manipulation parameters
        goal_msg.object_name = obj_name
        goal_msg.operation = 'grasp'  # Could be 'grasp', 'place', 'move', etc.

        goal_future = self.manipulation_client.send_goal_async(goal_msg)
        rclpy.spin_until_future_complete(self, goal_future)

        goal_handle = goal_future.result()
        if not goal_handle.accepted:
            return ActionResult(success=False, message='Manipulation goal rejected')

        result_future = goal_handle.get_result_async()
        rclpy.spin_until_future_complete(self, result_future)

        result = result_future.result().result
        return ActionResult(success=True, message='Manipulation completed')

    def execute_detection_action(self, action):
        """Execute object detection action"""
        if not self.object_detection_client.wait_for_service(timeout_sec=1.0):
            return ActionResult(success=False, message='Object detection service not available')

        request = DetectObjects.Request()
        area = action['parameters'].get('room_area', 'all')
        request.area = area

        future = self.object_detection_client.call_async(request)
        rclpy.spin_until_future_complete(self, future)

        response = future.result()
        if response.success:
            # Publish detection results
            status_msg = String()
            status_msg.data = f'Detected {len(response.objects)} objects in {area}'
            self.status_pub.publish(status_msg)
            return ActionResult(success=True, message=status_msg.data)
        else:
            return ActionResult(success=False, message='Object detection failed')

    def execute_clarification_action(self, action):
        """Handle clarification requests"""
        message = action['parameters'].get('message', 'Need clarification')

        # In a real system, this might trigger a speech output or GUI prompt
        self.get_logger().info(f'Requesting clarification: {message}')

        status_msg = String()
        status_msg.data = f'Clarification requested: {message}'
        self.status_pub.publish(status_msg)

        return ActionResult(success=True, message=message)

    def get_coordinates_for_location(self, location_name):
        """Convert location name to coordinates (simplified lookup)"""
        # This would normally come from a map or semantic localization system
        location_map = {
            'kitchen': (2.0, 1.0),
            'living_room': (0.0, 0.0),
            'bedroom': (-1.0, 2.0),
            'office': (-2.0, -1.0),
            'bathroom': (1.0, -2.0)
        }
        return location_map.get(location_name.lower())

class ActionResult:
    """Simple result class for action execution"""
    def __init__(self, success, message):
        self.success = success
        self.message = message

def main(args=None):
    rclpy.init(args=args)

    executor = VLAActionExecutor()

    # Example usage - this would normally come from LLM planning
    sample_plan = {
        'actions': [
            {
                'action_type': 'navigate_to',
                'parameters': {'target': 'kitchen'},
                'description': 'Go to the kitchen'
            },
            {
                'action_type': 'detect_objects',
                'parameters': {'room_area': 'kitchen'},
                'description': 'Look for objects in the kitchen'
            }
        ]
    }

    success = executor.execute_action_plan(sample_plan)

    if success:
        print("Action plan executed successfully!")
    else:
        print("Action plan execution failed!")

    executor.destroy_node()
    rclpy.shutdown()

if __name__ == '__main__':
    main()
```

        result_msg = VLAAction.Result()

        target_obj = goal_handle.request.target_object
        target_loc = goal_handle.request.target_location

        feedback_msg.current_status = f'Processing {action_type} action'

from functools import wraps

def measure_execution_time(func):
    """Decorator to measure action execution time"""
    @wraps(func)
    def wrapper(self, *args, **kwargs):
        start_time = time.time()
        result = func(self, *args, **kwargs)
        end_time = time.time()
        execution_time = end_time - start_time
        self.get_logger().info(f'{func.__name__} executed in {execution_time:.2f} seconds')

### Parallel Action Execution

For complex tasks, we might want to execute actions in parallel where possible:

```python
import asyncio
from concurrent.futures import ThreadPoolExecutor

class ParallelVLAActionExecutor(VLAActionExecutor):
    def __init__(self):
        super().__init__()
        self.executor = ThreadPoolExecutor(max_workers=4)

    async def execute_parallel_actions(self, actions):
        """Execute multiple actions in parallel where possible"""
        tasks = []

        for action in actions:
            # Check if action can be executed in parallel
            if self.can_run_in_parallel(action):
                task = asyncio.get_event_loop().run_in_executor(
                    self.executor,
                    self.execute_single_action,
                    action
                )
                tasks.append(task)
            else:
                # Execute sequentially if not parallelizable
                result = self.execute_single_action(action)
                if not result.success:
                    return False

        # Wait for all parallel tasks to complete
        results = await asyncio.gather(*tasks, return_exceptions=True)

        # Check if any task failed
        for result in results:
            if isinstance(result, Exception) or (hasattr(result, 'success') and not result.success):
                return False

        return True

    def can_run_in_parallel(self, action):
        """Determine if an action can run in parallel with others"""
        # Some actions must be sequential (e.g., grasp after navigation)
        sequential_actions = ['grasp_object', 'place_object']
        return action['action_type'] not in sequential_actions
```

## Error Handling and Recovery

### Action Retry Logic

Implement retry logic for failed actions:

```python
import time
from typing import Optional

class ResilientVLAActionExecutor(OptimizedVLAActionExecutor):
    def __init__(self, max_retries=3, retry_delay=1.0):
        super().__init__()
        self.max_retries = max_retries
        self.retry_delay = retry_delay

    def execute_single_action_with_retry(self, action):
        """Execute action with retry logic"""
        for attempt in range(self.max_retries):
            try:
                result = self.execute_single_action(action)

                if result.success:
                    return result
                else:
                    self.get_logger().warning(
                        f'Action {action["action_type"]} failed on attempt {attempt + 1}, retrying...'
                    )

                    if attempt < self.max_retries - 1:
                        time.sleep(self.retry_delay)

            except Exception as e:
                self.get_logger().error(f'Exception during action execution: {str(e)}')

                if attempt < self.max_retries - 1:
                    time.sleep(self.retry_delay)

        # If all retries failed
        return ActionResult(
            success=False,
            message=f'Action {action["action_type"]} failed after {self.max_retries} attempts'
        )

    def execute_action_plan_with_retry(self, action_plan):
        """Execute plan with individual action retry logic"""
        for i, action in enumerate(action_plan.get('actions', [])):
            self.get_logger().info(f'Executing action {i+1}/{len(action_plan["actions"])}: {action["action_type"]}')

            result = self.execute_single_action_with_retry(action)

            if not result.success:
                self.get_logger().error(f'Action failed after retries: {action["action_type"]}')
                return False

        self.get_logger().info('All actions completed successfully')
        return True
```

## Conclusion

ROS 2 action generation is the critical link between high-level planning from LLMs and low-level robot execution. Key considerations include:

1. **Action Design**: Design appropriate action types for your robot's capabilities
2. **Execution Flow**: Implement proper goal-feedback-result patterns
3. **Error Handling**: Include retry logic and graceful failure handling
4. **Timing**: Monitor and optimize execution times to meet performance requirements
5. **Integration**: Ensure seamless connection between LLM planning and action execution

The VLA pipeline brings together speech recognition, language understanding, and action execution to create a complete natural language interface for robotics.
