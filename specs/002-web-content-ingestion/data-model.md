# Data Model: Web Content Ingestion and Vector Embedding Pipeline

## Core Entities

### Content Chunk
**Description**: Represents a segment of extracted text from the book
- **Fields**:
  - `id` (string): Unique identifier for the chunk
  - `text` (string): The actual text content of the chunk
  - `url` (string): Original URL where the content was found
  - `section` (string): Section identifier from the source document
  - `chunk_index` (integer): Position of this chunk within the source content
  - `source` (string): Source identifier (e.g., "web_content")
- **Validation**: Text must not be empty, URL must be valid
- **Relationships**: Associated with one Vector Embedding

### Vector Embedding
**Description**: Numeric representation of content semantics generated by the Cohere model
- **Fields**:
  - `id` (string): Unique identifier for the embedding (matches Content Chunk ID)
  - `vector` (array of floats): The actual embedding vector (768 dimensions for Cohere)
  - `content_chunk_id` (string): Reference to the associated Content Chunk
- **Validation**: Vector must have exactly 768 dimensions, content_chunk_id must exist
- **Relationships**: Associated with one Content Chunk

### Configuration Parameters
**Description**: Settings that control the ingestion process
- **Fields**:
  - `source_url` (string): Base URL of the GitHub Pages site to crawl
  - `chunk_size` (integer): Size of text chunks in characters (default: 512)
  - `chunk_overlap` (integer): Overlap between chunks in characters (default: 128)
  - `cohere_model` (string): Cohere model name to use (default: "multilingual-22-12-embed")
  - `qdrant_collection` (string): Name of the Qdrant collection (default: "rag_embedding")
- **Validation**: Source URL must be a valid URL, chunk_size must be positive
- **Relationships**: Not directly related to other entities

## Qdrant Collection Schema

### rag_embedding Collection
**Vector Configuration**:
- Size: 768 dimensions
- Distance: Cosine similarity

**Payload Fields**:
- `text` (string): The text content of the chunk
- `url` (string): Original URL where the content was found
- `section` (string): Section identifier from the source document
- `chunk_index` (integer): Position of this chunk within the source content
- `source` (string): Source identifier (e.g., "web_content")

## State Transitions

### Content Processing States
1. **Discovered**: URL identified during crawling phase
2. **Extracted**: Text successfully extracted from the page
3. **Chunked**: Text divided into semantic chunks
4. **Embedded**: Embedding successfully generated for the chunk
5. **Stored**: Embedding stored in Qdrant with metadata
6. **Failed**: Error occurred at any stage of processing

## Validation Rules

### Content Chunk Validation
- Text length must be greater than 0
- URL must be a valid HTTP/HTTPS URL
- Chunk index must be non-negative

### Vector Embedding Validation
- Vector must contain exactly 768 values (for Cohere embeddings)
- All vector values must be finite numbers
- Associated content chunk must exist

### Processing Validation
- Each URL must be processed within a timeout period
- Failed chunks must be logged for debugging
- Duplicate content detection to avoid redundant embeddings
